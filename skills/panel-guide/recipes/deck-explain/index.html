Data structures

Hash maps,
collisions included

How a key finds its value in one step, and what happens when two keys want the same spot.

Claim to open with: a hash map is an array plus a function. Everything else is handling the case where the function repeats itself.

The idea

A function turns the key into an array index

  • Key "ada"
  • hash()
  • index 1
  • Value
  • any string
  • mod array size
  • one lookup
    •  const index = hash("ada") % buckets.length; // 4471 % 6 = 1 return buckets[index]; // one lookup, no search
    No searching: the key itself says where to look. That is why lookup time does not grow with the number of entries, as long as the function spreads keys out.

    The problem

    Two keys, one bucket

    0
    1"ada"
    2"bob""eve"
    3
    4
    5

    hash("eve") = 2, same as "bob". Chaining keeps both in the bucket as a short list.

    Click once: eve arrives and lands on top of bob. With a finite array and unlimited keys this is guaranteed to happen, so the design question is how cheaply you handle it. Chaining is one answer; probing the next free slot is the other.

    The cost

    Crowded tables get slow, fast

    x: load factor (entries / buckets). Textbook formulas: chaining 1 + a/2, linear probing (1 + 1/(1-a)) / 2.

    Both are fine while the table is mostly empty. Past 0.7 linear probing climbs steeply because filled slots clump together. Chaining degrades gently. The numbers come from the standard average-case formulas, not a benchmark.

    The rule of thumb

    0.75

    grow the array when it is three quarters full

    Java's HashMap resizes at that load factor by default.

    Resizing rehashes every key into a bigger array, which is expensive once, and keeps the load factor low forever after. That trade is why inserts are fast on average.

    Takeaways

    Three things to keep

    • Lookup is one hash and one index, not a search.
    • Collisions are certain, so every design has a plan for them.
    • Keep the table under about 75% full and it stays fast.
    Close by asking what the audience would pick for a table that must never resize: chaining, for its gentle failure mode.
