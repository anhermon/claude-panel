Why exponential backoff alone still stampedes, and the one-line fix.

Open with the claim: retries without jitter make an outage longer, not shorter. Five slides: the problem, a simulation, the intuition, the numbers, the decision.

The problem

Backoff alone keeps the herd in step

  • The upload endpoint returns 503. All 60 clients fail in the same instant.
  • Every client waited the same 500 ms. 60 requests land in one 100 ms window.
  • The wait doubled, for everyone. The wave is just as tall.
  • The server never gets room to recover. Each wave hits a machine that is still down.
    •
    Walk down the timeline. The point: doubling the wait spaces the waves out, it does not break them up. Every client still retries at exactly the same moments, so the server sees 60 requests at once, over and over.

    Intuition

    Retry space

    Each retry picks a point inside a window that doubles every time. Without jitter the point is always the edge; with jitter it can be anywhere inside.

    Drag to orbit, scroll to zoom.

    The knot is a stand-in for the space of possible retry moments: a path that never lands on the same point twice. Drag it around. This is the only slide where the picture is the intuition, not the data.

    The numbers

    // full jitter function retryDelay(attempt) { const ceiling = 500 * 2 ** attempt; return Math.random() * ceiling; }

    Simulated, not measured: 60 clients, 4 retries, base 500 ms, averaged over 500 seeded runs. Fixed and plain exponential both peak at all 60 clients. Equal jitter halves that; full jitter cuts it to about a third. The right-hand side is the whole change.
